Agent 框架：能力趋同之后，垂直行业还卡在哪里

主流框架都在收敛成同一套运行时，接口协议也归到了一个基金会。垂直行业卡在可靠性和问责上，金融、医疗的做法是收窄 Agent 自己能决定的范围。

00要点

  1. 框架在收敛成同一套运行时微软 Agent Framework 4 月发布 1.0，8 月运行时正式可用，上下文压缩、工具审批默认打开。
  2. 接口协议归到了一处AAIF 成立不到一年，托管的项目从 3 个增至 10 个，MCP、A2A、AGENTS.md、Agent Skills 都在其中。
  3. 准确率在涨，稳定性没跟上PhysicianBench 上最好的 GPT-5.5 单次通过率 46.3%，同一题连做三次都对只有 28.0%。
  4. 框架要和模型成对评FrontierHarness 测 22 种框架配置，成本差异 92.8% 来自模型，框架本身只占 2.3%。
  5. 金融、医疗在收窄自主权BCG 调查的 26 家系统重要性银行里，73% 允许 Agent 在选定场景上线，只有 8% 有统一的 Agent 监控。

02招熟 · 上手即用

先选运行时，再谈编排；能用单 Agent 就不上多 Agent。

  1. 按运行时能力选框架

    编排图各家都有，差别在运行时：状态能否持久化、中断后能否续跑、工具调用能否设审批、有没有内置追踪。LangGraph 1.0 和微软 Agent Framework 都把这几项做成了内置功能。

    授信审核跑到一半要等审批人签字，状态要能存下来，第二天接着跑。

  2. 换模型就重测框架

    FrontierHarness 的数据里，Codex CLI 配 GLM-5.3 时每任务成本排第 1，配 Kimi-K3 时排第 16。只看一个模型的排名选框架，换了模型就可能选错。

    把线上模型换成国产模型前，先用同一套任务集重跑两三个候选框架。

  3. 工具走 MCP，流程写成 Skills

    工具接口按 MCP 包装，固定流程写成带 SKILL.md 的技能文件夹。两者都由 AAIF 托管，换框架时不用重写。

    把病历取数接口包成 MCP 服务，把临床试验入组筛查写成一份技能。

  4. 先用单 Agent 加固定流程

    伯克利分析了 7 个多 Agent 框架的 1642 条运行记录，任务失败率在 41% 到 86.7% 之间。排在前面的是重复步骤和不知道何时该停，都出在系统设计上。

    理赔初审先用一个 Agent 按固定步骤走，跑稳了再拆角色。

  5. 读写分开授权

    摩根大通只允许外部 Agent 读余额，不能转账。FSB 的咨询稿也建议列出禁止的动作和需要人批的动作，超过金额阈值的交易要双人复核。

    财富管理 Agent 只出调仓建议，下单交回客户在银行渠道确认。

  6. 代码执行放进外置沙箱

    Agent 留在沙箱外，要执行的代码发进专用沙箱，出网走白名单，API 密钥由代理注入。中了提示注入，坏的也只是沙箱。

    让 Agent 分析交易流水前，先把它的代码执行挪进沙箱，只放行行内数据接口。

  7. 上线前静默运行，实测几档自主程度

    斯坦福的万古霉素给药 Agent 静默运行两个月，高自主版误差 21.8%，限制更多的低自主版反而是 37.8%。收紧权限不一定更安全，要实测。

    给药建议先和药师处方逐条对比，以第二位药师的一致率作为达标线。

  8. 验收看连续成功率

    单次通过率会高估稳定性。同一任务跑三到五次，看是否每次都对（pass^k），再决定能否放到无人值守的环节。

    病历摘要 Agent 每条样本跑五次，五次都对的比例低于九成就保留人工复核。

03懂劲 · 原理机制

框架的分量在模型之外的那层运行时，可靠性和安全都要在这一层兜住。

  1. 运行时是框架的主体

    MBZUAI 按行数给泄露出的 Claude Code 分类，估计约 98.4% 是运行时基础设施，决策逻辑只占约 1.6%。作者说明这是粗略的行数统计。微软 8 月正式发布的运行时，把上下文压缩、待办清单、文件记忆、工具审批和追踪都默认打开。

  2. 持久执行：把 Agent 当成长事务

    每一步之后写检查点，进程重启或等人审批时从检查点恢复。LangGraph 1.0 把它叫作持久状态（Durable State），人工介入就是在某个检查点上暂停。

  3. 成本由步数决定

    每一步都要把上下文重发一遍。FrontierHarness 测得一次运行平均消耗 200 万到 480 万输入 token，决定成本的是步数，不是提示长度、工具数量或缓存命中率。上下文压缩和尽早停止，都是在省步数。

  4. 多 Agent 的失败可以分类

    伯克利的 MAST 把失败分成 14 种、3 大类：系统设计、Agent 之间失配、任务验证。最常见的是重复步骤（15.7%）、推理和行动不一致（13.2%）、不知道终止条件（12.4%）。

  5. 可靠性有四个维度

    普林斯顿用 12 个指标测 15 个模型，分一致性、稳健性、可预测性和安全四类。两年里准确率涨了不少，同一任务多次运行的一致性却改善很少，提示换个说法结果就变。

  6. 提示注入靠架构防

    CaMeL 先让一个模型只看可信指令、写出执行计划，不可信数据只能当值传递，不能改动计划。在 AgentDojo 上它以可证明的安全完成 77% 的任务，不设防的系统是 84%。同组研究者还总结了六种设计模式，比如先定计划再执行、双模型隔离。

  7. 收窄 Agent 能自己决定的环节

    药物警戒系统 MedCheckpoint 执行前锁定研究设计参数，患者层面的统计交给人写的确定性工具，分析不可行就中止。碰到测不了的结局时，编程 Agent 基线在 21 次运行里最多出 2 次误导性结果，它一次也没有。数据是模拟的。

  8. 监管按后果和放权程度分级

    美联储等三家机构 4 月发布的 SR 26-2 在脚注里把生成式和 Agent 类模型排除在模型风险管理之外，交回银行自己的风险管理。OCC 的检查框架按出错后果、放给 AI 多少行动权和人工监督程度决定审查力度。

04神明 · 长期方向

框架之争会变成运行平台之争，胜负看谁能让 Agent 可审计、可问责。

  1. 框架变成托管平台

    InfoQ 的判断是，Agent 框架正从构建 Agent 的开发包，变成运行 Agent 的受治理平台。微软的托管 Agent 按用量计费，本地、容器和托管环境跑同一个程序。

  2. 协议统一了接口，信任还要自己建

    MCP 和 A2A 解决了怎么连，没有回答这个 Agent 该不该信。Agent 身份、授权范围和审计记录，目前仍由各家自己实现。

  3. 人盯不过来，转向自动监控

    FSB 指出，Agent 为一个目标可能走几百个中间步骤，人工实时监督不现实。监督会转向自动监控加完整的审计记录。

  4. 训练环境开始共享

    Hugging Face 把强化学习环境框架 OpenEnv 捐给 AAIF。垂直行业以后可以把自己的流程做成训练环境，用来训练和评测 Agent。

  5. 稳定性指标进入验收

    单次准确率掩盖了不稳定。我们判断，连续成功率和多次运行的一致性会写进采购和上线验收的标准。

07行动建议

  1. 列一张运行时能力清单（续跑、压缩、审批、追踪），拿手上的两三个候选框架逐项打勾，缺两项以上的不进生产。
  2. 建一套 50 到 100 题的业务任务集，换模型或换框架时重跑，每题跑五次，记单次通过率、连续成功率和每任务成本。
  3. 给每个 Agent 写一页权限表：读哪些数据、能做哪些动作、哪些动作要人批，表外的动作由运行时拦截。
  4. 把一个高频流程的工具包成 MCP 服务、流程写成 Skills，在两个不同框架里各跑一遍，验证换框架不用重写。
  5. 新的医疗或金融 Agent 先静默运行一个月，与人工决策逐条对比，一致率达到第二位专家的水平再放权。

08待解问题

  • 美国银行监管把 Agent 类模型排除在模型风险管理之外，谁来验证 Agent，目前只有原则，没有方法。
  • 连续成功率怎么算达标没有行业标准，医疗和金融各自的阈值都要从头定。
  • 协议统一了接口，跨机构 Agent 的身份认证和责任划分还没有公认做法。
  • 多 Agent 在哪些任务上确实胜过单 Agent，缺少同一任务、同一模型下的对照数据。
