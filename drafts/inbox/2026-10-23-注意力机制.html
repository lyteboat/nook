注意力机制：机器怎么“一目十行”

2026-10-23 · 讨论 · 目标章节：第 1 章 大模型是如何工作的 · 状态：讨论中 · 阶段：招熟

开题

问题《Attention Is All You Need》说机器能有“注意力”，能自动找到哪些词最相关。这到底是怎么做到的？
场景弄懂原理，能把计算过程讲清楚、能手推。
目标阶段招熟

一句话：注意力（Attention）本质上是一次模糊的字典查询（soft key-value lookup）：每个词拿自己的 Query 去和句子里所有词的 Key 比相似度，按相似度把所有词的 Value 加权混合，得到自己的新表示。它不是精确匹配，也不是去查整个世界的词，只在当前输入里查。

全景图

招熟：会用 如何做

心法：一个公式，四步计算

Attention(Q, K, V) = softmax(QKᵀ / √dₖ) · V

Q、K、V 为什么这么叫

名字来自信息检索（Information Retrieval）。每个词同时扮演三个角色。

搜索引擎Java HashMap注意力
Query搜索框里敲的话get(key) 的参数我要找什么
Key网页的标题和标签存进去的 key我能被什么找到
Value网页正文key 对应的 value找到后我提供什么
匹配方式按相关度排序完全相等才命中，只返回一个和所有 Key 比相似度，按权重混合所有 Value

Key 和 Value 要分开，因为“凭什么被找到”和“找到后给什么”是两回事，就像书的目录标题和正文。分开后模型可以用一套特征匹配、另一套特征传递信息。

注意：真实的 Q、K、V 只是一串数字，没有人能读懂的含义。“它在找一个会累的名词”这类说法只是帮助理解的比喻。

招式（按重要性排序）

#招式做什么工程类比
1词变向量每个词先变成一个向量（Embedding）查一张固定的 Map<词, float[]>
2一分为三向量乘三个矩阵，得到 Q、K、V同一个对象实现三个接口
3打分Q 和每个 K 做点积，越像分越高计算相关度分数
4缩放分数除以 √dₖ，防止数值太大归一化，避免溢出式的极端值
5归一softmax 把分数变成加起来为 1 的权重把分数换算成百分比
6加权求和用权重把所有 V 加起来按占比合并多个结果
7多头（Multi-Head）同时用多组 Q/K/V，各自关注不同的关系；原论文用 8 组同一份数据建多个索引

“同时查所有词”的两层意思

层次含义
查所有词每个词都和这次输入里的每个词比一遍，包括它自己，不管距离多远。结果是一张 n × n 的分数表。
同时所有词的 Q 叠成矩阵，K 也叠成矩阵，一次 Q × Kᵀ 算出整张表。可以并行，GPU 擅长。

例：“动物没有过马路，因为它太累了”中，“它”这一行的权重（数字为示意）：

动物没有过马路它累
它0.550.030.020.100.150.15

例子：手算一遍

句子只有 3 个词：猫、坐、它。假设 Q、K、V 已算好，都是 2 维（dₖ = 2）。只算“它”这一行，“它”的 Query = (2, 0)。

词KeyValue① Q·K② ÷ √2③ softmax
猫(1, 0)(1, 0)21.410.58
坐(0, 1)(0, 1)000.14
它(0.5, 0.5)(0.5, 0.5)10.710.28

④ 加权求和：0.58 × (1, 0) + 0.14 × (0, 1) + 0.28 × (0.5, 0.5) ≈ (0.72, 0.28)。“它”的新向量明显偏向“猫”的 (1, 0)，模型由此“知道”它指的是猫。

懂劲：知道为什么 为何如此

这次以招熟为主，下面是讨论中顺带讲到的几点。

心法：“查什么”是学出来的

没人规定“它”的 Query 要和“动物”的 Key 对上。W_Q、W_K、W_V 一开始是随机的，模型预测下一个词出错时，反向传播（Backpropagation）会调整它们。注意力只规定了“怎么查”，“查什么”是训练出来的。

心法：上下文和参数，两种“记忆”

生成时，每个词只能看已经出现的词，看不到后面还没写的，这叫因果掩码（Causal Mask）。

为什么要除以 √dₖ

真实模型里每个 Key 有 64 维甚至更多（原论文 dₖ = 64），点积是几十项相加，数值会很大，softmax 就会“赢家通吃”。

分数softmax 后的权重结果
1.41, 0, 0.71（缩放后）0.58, 0.14, 0.28有主有次，其他词也能分到信息
16, 0, 8（放大 8 倍）0.9997, 0.0000, 0.0003几乎全押一个词，训练时梯度传不过去

相邻概念：和 RNN 比

RNN注意力
怎么读一个词一个词，第 i 步等第 i−1 步所有词同时算
远距离信息越传越淡第 1 个词和第 100 个词一样近
并行难一次矩阵乘法，GPU 友好
工程类比有依赖的 for 循环parallelStream()

相邻概念：和向量检索比

向量检索（如 RAG 里的相似度搜索）注意力
比什么两个原始 embedding 直接比先乘 W_Q、W_K，换成“提问视角”和“被找视角”再比
怎么算常用余弦相似度，做了长度归一化点积再除以 √dₖ，不做长度归一化
对称吗对称：A 和 B 的相似度等于 B 和 A不对称：“它”看“动物”的分数不等于“动物”看“它”
比较规则固定训练学出来
输出排好序的 top-k 结果按权重混合所有 Value，得到这个词的新向量
做几次一次查询每一层都做一遍，大模型有几十层，越往上混进的上下文越多

相邻概念：自注意力和交叉注意力

Query 来自Key / Value 来自例子
自注意力（Self-Attention）这句话同一句话“它”在本句里找“动物”
交叉注意力（Cross-Attention）正在生成的句子另一句话翻译时，正在写的中文去查英文原句

权衡与缺陷

代价原因后果
计算量 O(n²)每个词都要和每个词比，表的大小是 n × n文字长度翻倍，计算量翻四倍；上下文窗口因此有上限

神明：点到为止 本质

注意力把“信息该从哪里来”这件事本身，变成了可以学习的东西。

我的看法

简单理解：注意力机制就是把一句话里的每个词元（Token）两两算相似度、打分，找出哪些词和它相关，背后是并行的矩阵计算。它和我平时说的向量相似度是一类东西，只是自己和自己比（自注意力）。

讨论后补准的三点：

  1. 不只找相关，还要混合：打完分会按权重把所有词的 Value 加起来，改写出这个词的新向量，输出不是一份排名。
  2. 比的是投影后的向量：先乘训练出来的 W_Q、W_K 再比，所以比较规则是学出来的，而且不对称。
  3. 逐层反复做：每一层都改写一遍，越往上，每个词带的上下文越多。

待解决

  • 多头注意力：8 组头各自学到了什么关系，最后怎么合并
  • 位置编码（Positional Encoding）：注意力本身不看顺序，词序信息从哪来
  • O(n²) 的应对：长上下文模型怎么降低计算量
  • 注意力之后的前馈网络（FFN）做了什么，知识具体怎么存在参数里
  • 用十几行 PyTorch 代码复现上面的手算

过招中的好问题

#问题简答
1谁规定“它”的 Query 要和“动物”的 Key 对上？没人规定，W_Q、W_K、W_V 靠训练学出来。详见“懂劲：‘查什么’是学出来的”。
2Key 和 Value 为什么要分开？“凭什么被找到”和“找到后给什么”是两回事，像书的目录标题和正文。
3“同时查所有词”，查的是这次输入的词，还是世界上所有的词？只查这次输入。世界知识存在参数里。详见“上下文和参数，两种‘记忆’”。
4为什么要除以 √dₖ？维度大时点积很大，softmax 会赢家通吃，梯度传不过去。
5每个词都看所有词，长文章怎么办？计算量是 O(n²)，这是上下文窗口有上限的原因。
6注意力和平时说的向量相似度是一回事吗？是一类，但注意力比的是投影后的向量、不对称，并且会混合 Value。详见“和向量检索比”。
7这种“改写”只做一次吗？每一层都做一遍，大模型有几十层。
