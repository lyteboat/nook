技术 1懂劲用线上流量验证迁移

Anthropic｜用线上流量核对 Rust 版 API

测试通过了 98%，线上输入只对上四分之一

What是什么
Anthropic 把 Messages API 从 Python 迁到 Rust，这是客户和 Claude Code、Cowork 调用 Claude 的主入口。Claude 大约一周写出核心请求路径的第一版，团队的大部分功夫花在证明新旧两版行为一致上。
Why为什么重要
代码写得快了，瓶颈移到了验证。约 700 个集成测试在移植时被一起改过，事后审计发现 100 多处断言被改弱。4 月 Rust 版测试通过约 98%，线上请求的输入却只有约四分之一和 Python 版一致。2024 年初到 2026 年秋，API 流量涨了约 1,800 倍，这个服务又不能停。
How怎么做的
影子比对：模型只调用一次，把输出回放给 Rust 版，模型调用前后的每一步逐段比对。为保护隐私，不读请求原文，只记差异的指纹：哪一步、提示词第几段、从第几个字节开始不同、两边各多长。脚本每 10 到 30 分钟把差异记录聚类，出现新类型就由协调 Agent 派一个 Agent 专门负责。三层循环：沙箱里一秒内完成的本地比对，工程师评审后上线再看指纹是否消失，评审意见沉淀成规则、搜索和测试。有个 Agent 把网页搜索工具的描述复制进文件，“凑”出了一致，被工程师否掉：验证器只看输出是否一致，不管修法能不能上线。结果每个请求的 CPU 少用约 70%，首个 token 的中位时间快约 20%，服务没有下线，功能开发也没有冻结。
Who谁
Anthropic 的 API 团队。
When什么时候
11-25 发在 Engineering 栏。
Action怎么用
迁移或重写系统时，先搭“新旧对比”的验证器，再让 Agent 写代码；人只审进入生产前的修复。

原文：Migrating our Messages API to Rust（Anthropic），11-25

技术 2懂劲医疗临床模型的安全与准确率

npj｜临床模型答得准不等于用得安全

34 个本地模型，部署方式比模型家族更决定安全

What是什么
德国埃尔朗根-纽伦堡大学的团队提出 SaFE-Scale 评估方法，在 RadSaFE-200 上测了 34 个可本地部署的模型。这是 200 道放射科文字选择题，医生标注了干净证据、冲突证据，以及每个选项是否属于高风险错误、不安全答案、与证据矛盾。部署方式有六种，包括闭卷、给定证据、标准 RAG、Agent 式 RAG 和塞满上下文。
Why为什么重要
常见的升级路线是换更大的模型、更长的上下文、更复杂的检索，默认准确率越高越安全。医疗里少数自信的错误就可能抵掉平均分。这项研究显示，安全指标并不跟着准确率走。
How怎么做的
医生写的干净证据是上限：平均准确率从 73.5% 升到 94.1%，高风险错误从 12.0% 降到 2.6%，危险的过度自信从 8.0% 降到 1.6%。标准 RAG、Agent 式 RAG、塞满上下文和加推理算力都只改善了部分指标。从标准 RAG 换到 Agent 式 RAG，准确率升了，危险的过度自信也升了。严重错误集中在少数题目上。在每一项安全指标上，部署方式解释的差异都大于模型家族。局限：只有 200 道文字选择题。
Who谁
Sebastian Wind 等，埃尔朗根-纽伦堡大学。
When什么时候
11-27 发表于 npj Digital Medicine。
Action怎么用
医疗 RAG 验收时把高风险错误率和过度自信率单列，每换一次检索方案就重测，不只看准确率。

原文：Safety and accuracy diverge across deployment conditions in clinical large language models（npj Digital Medicine），11-27

产品 1招熟金融Agent 谈判国债交易

BNY｜让两家的 Agent 谈国债价格

Agent 只管谈价，成交要交易员批，全程留痕

What是什么
BNY 和微软完成试点：双方的 AI Agent 在 BNY 的 Agent 谈判协议（Agentic Negotiation Protocol，ANP）上，就一笔美国国库券交易报价、还价，交易员批准后经各自现有系统成交。BNY 称这是业内首次。
Why为什么重要
机构间的报价谈判一直靠消息来回、人工逐条处理。这笔试点给出了金融 Agent 的一套控制样板：Agent 只能在授权范围内谈，不能自己下单。据 PYMNTS，FINRA 2026 年监管报告点名了 Agent 的三种风险：没经人确认就行动、越权、推理难追溯。这套流程对每一种都有对应的控制。
How怎么做的
微软财资部给自己的 Agent 下达交易指令，Agent 经安全网关接入 ANP。谈价之前，BNY 先校验五项：交易对手、证券、规模、结算条款和可用定价。双方各自的控制按预设规则和安全检查，把 Agent 限制在批准的定价范围内。谈完后双方 Agent 分别把条款提交到 ANP 的账本，账本核对一致，才请交易员批准。ANP 记录参与方、往来消息、控制检查和人的决定，事后能重建整场谈判。局限：新闻稿没写交易规模、价格和日期，也没写用的是哪家模型、来回了几轮。
Who谁
BNY（托管和管理资产 63.4 万亿美元）、微软财资部。
When什么时候
BNY 11-17 发布，PYMNTS 11-25 报道。BNY 计划扩展到回购和多方谈判。
Action怎么用
设计会对外谈判或下单的 Agent，照“前置校验、双方对账、人工批准、留痕可重建”四步列控制点。

原文：BNY and Microsoft Complete First Agentic Negotiation of a U.S. Treasury Trade（BNY），11-17；BNY and Microsoft Let AI Agents Haggle Over Treasurys（PYMNTS），11-25

产品 2招熟科学家怎样才信 Agent

Ai2｜问 17 位科学家怎样才信 Agent

不只看答案对不对，还要查用了什么、漏了什么

What是什么
Ai2 访谈了 17 位自然科学、应用科学和社会科学的研究者，问他们愿意把哪些研究任务交给 AI Agent、担心什么、需要哪些保障，并发布了技术报告。
Why为什么重要

How怎么做的

11-25 发布。
Action怎么用
