技术 1懂劲FlashProve 可证明推理

Anthropic｜开源 FlashProve，证明回答来源

用户第一次能自己验证 API 背后跑的是哪个模型

What是什么
Anthropic 前沿红队开源 FlashProve：模型提供方先对一套权重做承诺，之后为每条回答生成零知识证明，证明它确实由这套权重生成，且不泄露权重。
Why为什么重要
金融、医疗的审计常要回答“当时用的是哪个模型、哪个版本”，目前只能信厂商的日志。可证明推理把这件事变成可以独立验算的证据，离生产还远，但原型已经跑通。
How怎么做的
在 4 位量化的 Llama 4 Maverick（4000 亿参数 MoE）上，单张 H100 每秒生成约 110 个 token 的证明，是 vLLM 推理 GPU 时间的 70 到 95 倍。每 1,024 个 token 的证明约 19 MB，CPU 验证约 17 秒。一次承诺约 39 分钟，可用于约 1,600 万次请求。局限：只覆盖贪心解码和整数化权重，上下文限 1,024 token，不防时序侧信道，模型架构不保密。
Who谁
Anthropic 前沿红队的 Roy Rinberg、Alex Allain，合作者来自 EPFL、MIT、StarkWare 和 Succinct。
When何时
11-02 发布，Apache 2.0 开源，附技术报告、协议规范和 Lean 证明。仓库标明是研究原型，不再维护。
Action行动建议
在模型审计清单里加一项“能否证明调用的模型版本”；向供应商问清版本锁定和变更通知机制，先用合同条款补上，等可证明推理成熟再换成技术手段。

原文：Progress on provable inference for large language models（Anthropic Research），11-02

技术 2招熟医疗决策模型当医疗评审

西奈山等｜测得决策模型评医疗回答一致率持平

便宜的评审能当初筛，漏项仍要大模型和人补查

What是什么
研究者让只输出结构化概率的决策模型 TypeSafe Jev 1.13 当评审，给医疗 AI 的回答打分，与 GPT-6.1 Sol、Claude Opus 5.5 两个前沿评审和专家标注对比。
Why为什么重要
LLM 评审的成本常比被评的模型还高，评审量一大就压不住。10-28 那期写过决策模型和 LLM 配对分诊，这篇给出了它当评审的硬数字：一致率不输前沿模型，成本低两个数量级。
How怎么做的
5 个公开基准、25,091 个评审单元、213,913 次模型调用。在 3,614 个共同单元上，与专家一致率 Jev 66.1%、Opus 65.0%、Sol 60.7%，六项任务中四项不劣于前沿模型。全量评审用 17 分钟、1.46 美元，单次成本约为 Sol 的 1/34、Opus 的 1/152。局限：同样误报率下，Jev 漏掉 55.6% 的植入遗漏，Opus 漏掉 48.1%；按 Jev 置信度从低到高复核，查出的错误是随机抽查的 1.4 倍，但这是模拟结果。
Who谁
Beth Israel Deaconess 医疗中心（哈佛医学院）和西奈山伊坎医学院，通讯团队含 Eyal Klang、Girish Nadkarni。
When何时
11-02，预印本，事先在 OSF 注册；分析代码尚未公开。
Action行动建议
评审流水线分两层：便宜的模型全量初筛，按置信度把最不确定的一批送前沿模型或专家；遗漏类错误单独抽检，不交给便宜评审；阈值按本地数据重新校准。

原文：A decision-only model as a low-cost judge of medical AI answers（medRxiv），11-02

产品 1招熟金融Arca 财富管理 Agent

Arca｜让 Agent 提议，交易和转账留给顾问

金融 Agent 推动流程，不可逆的动作由人来做

What是什么
财富管理公司 Arca 的 AI 工程负责人 Aman Singh 介绍他们的做法：Agent 做后台工作，顾问做最终决定，用他的话说是“Agent 给人发提示，多过人给 Agent 发提示”。
Why为什么重要
财富管理的任务最长要走十天，中间有多方参与和多次交接，不适合一问一答。Arca 把 Agent 设计成流程的推动者，权限边界用确定性规则写死，这套分工可以直接搬到信贷审批、理赔这类长流程。
How怎么做的
每个客户有一份持久记忆，记录历史、近期和长期任务以及每个动作的负责人，Agent 写入，顾问查看。交易和资金划转只能由顾问执行，限制是确定性的，不交给模型判断。计算在沙箱里跑，生成的代码转成固定格式后丢弃，数据过一道检查再进后端。一个元 Agent 读顾问反馈和运行轨迹，提出改进 harness 的建议。自建 harness，按内部基准给每类任务选模型，主力是 Claude。局限：播客自述，没有准确率、错误率等数字；Agent 本身不在沙箱里。
Who谁
Arca，近期完成 4,850 万美元融资，General Catalyst 领投，Index Ventures、Venrock 参投。
When何时
10-31，Latent Space 播客（录于 AI Engineer 纽约站），自述做法。
Action行动建议
设计金融 Agent 时，先列出不可逆动作（下单、转账、对外发送），用代码规则锁给人；其余步骤让 Agent 主动推进并把待办推给负责人；每个客户维护一份带负责人字段的任务记忆。

原文：Agents Prompt People: Using Agents for Long-Horizon Financial Work（Latent Space），10-31

全员自建工具的试验结束，编程 Agent 回到专业岗位

LeanGuard 团队｜用 Lean4 规则拦截 Agent 越权调用工具调用执行前，先过一道可证明的规则检查懂劲
What是什么
LeanGuard 在 Agent 的每次工具调用到达环境之前，用 Lean4 写的策略检查一遍，不合规就拒绝，可以把违反的规则反馈给 Agent，也可以自动找一个相近的合规调用。
Why为什么重要
金融、医疗 Agent 的权限规则大多写在提示词里，模型可以不听。把规则放到执行层并给出证明，拒绝与否就不再取决于模型。
How怎么做的
策略由状态谓词和执行历史上的时序算子组成，默认拒绝，判定过程证明与 LeanLTL 语义等价。在 Tau-Bench 上，5 个 Qwen 模型（0.8B 到 27B）不加防护时执行了至少 33 次策略禁止的调用，加上后为 0，任务成功率无显著变化。DTap 上直接提示注入的成功率从 57.9% 降到 5.9%。证明引导的修复在 252 次被拒调用中修好 88 次。局限：没有报告误拒率；只测了 Qwen 系列。
Who谁
Sreehari Sankar、Vipin Chaudhary 等 20 位作者。
When何时
11-02，arXiv 预印本，未见代码。
Action行动建议
把 Agent 的禁止动作从提示词搬到工具网关，按“状态加历史”写成规则，例如“未完成身份核验不得查询账户”；被拒时把规则原文回给 Agent，减少重复尝试。

原文：LeanGuard: Lean-Verified Guardrails for Tool-Using Agents（arXiv），11-02

佛罗伦萨大学｜测得通用模型过度建议就医健康问答里，模型越新越爱让人去看医生招熟医疗
What是什么

How怎么做的

James Zou 团队｜用 240 个任务测 Agent 当队友单独做得对的事，换成协作就可能做不好懂劲
What是什么
协作智能基准（Collaborative Intelligence Benchmark）用 240 个任务、8 个维度测 Agent 当队友的能力，比如拒绝不安全的捷径、检查较弱模型留下的工作。
Why为什么重要
Agent 在金融、医疗里多半与人或别的 Agent 一起干活。这个基准只在模型独立能做对的任务上计分，把协作能力和个人能力分开量。
How怎么做的

Sean Wu、James Zou 等。
When何时
11-02，arXiv 预印本；公开 160 个任务的代码和数据，80 个留作盲测。
Action行动建议

Ai2｜发布 StateBench，测长文档状态追踪长文档里的数值一路改写，前沿模型会跟丢懂劲
What是什么
StateBench 测模型能否在长文档里跟住变量的变化，分四级：只赋值一次、反复赋值、在当前值上累加、变量之间互相传值。
Why为什么重要
账户流水、病程记录都是“状态随文档改写”的结构。长上下文检索测得好，不代表能算对最终状态。
How怎么做的
Gemini 3.8 Flash、Claude Opus 5.5、GPT-6 Sol 和 Luna 在前两级表现好；到累加和互相传值两级，准确率随长度急降，最长的传值题只有 13% 或更低。同一任务换成电子表格编辑的写法，分数可以从接近满分掉到随机水平。从头训练的实验里，Gated DeltaNet 和混合架构能泛化到训练长度的约 250 倍，Transformer 学不会最难一级。局限：变量数固定，不覆盖中途出现新实体的情况。
Who谁
艾伦人工智能研究所（Ai2）。
When何时
11-03 发布，数据集在 Hugging Face 公开。
Action行动建议
需要从长记录里算余额、累计剂量这类最终状态的场景，不让模型直接读全文给答案，改成逐条抽取变更，再用代码计算。

原文：StateBench: Testing how language models track state changes over long documents（Hugging Face Blog），11-03

What是什么
PROMOTE 协议为研究 Agent 生成的交易规则设计“随时有效”的晋级检验：Agent 何时提出候选、盯多久都可以，误晋级的概率仍有上界。
Why为什么重要
Agent 生成规则的速度远超人工记录筛选过程，反复回测、看到好结果就上报，会系统性地放大假阳性。这是给量化研究 Agent 配的统计闸门。
