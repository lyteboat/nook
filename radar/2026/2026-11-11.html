技术 1懂劲VulnCheck 核对漏洞账本

VulnCheck｜核对 Anthropic 的漏洞账本

AI 找漏洞越找越多，分诊的活落到了维护者头上

What是什么
安全情报公司 VulnCheck 逐条核对 Anthropic Glasswing 项目七个月来的漏洞账本，对照 CVE 记录、GitHub 安全公告、Linux 内核提交和 curl 维护者的反馈。
Why为什么重要
上期写过 OpenAI 自报 Linux 内核里 948 个提权漏洞的候选补丁。这篇是少有的第三方账：厂商报的“发现”和维护者认的“漏洞”差得很远，而核实的成本由开源维护者承担。
How怎么做的
账本记了 37,966 条发现，公开 7,349 条（19.4%），标为已修复 217 条；查重 1,654 条，是已修复数的 7.5 倍。归到 Anthropic 名下的 CVE 共 442 个，只占今年 CVE 总量的 0.5%，进了在野利用清单的只有 2 个。9 月时 Claude 把 91.5% 的发现评为高危或严重，维护者只评了 51.3%。curl 收到的 34 份已处理报告里 19 份不是漏洞，确认的 6 份都是低危。Anthropic 自报的真阳性率却从 90.8% 升到 94.2%。局限：部分归属靠人工核对，curl 样本小，还有 9 份待评估。
Who谁
VulnCheck 的 Patrick Garrity；被核对的是 Anthropic 的 Glasswing 和 10 月上线的 OSS Scanner。
When何时
11-09 发布，数据截至 11-02。Hacker News 上 420 分。
Action行动建议
用 AI 扫漏洞时，按“维护者确认、已修复”统计成果，不按发现数；报告发出前先做去重和严重度复核，别把分诊成本转给下游。

技术 2懂劲AlphaProof Code

DeepMind｜用 Lean 证明 Signal 的编译代码

Agent 写证明，Lean 查证明，人只看 1%

What是什么
AlphaProof Code 是一套多模型协作的形式化验证（Formal Verification）框架：人定要证明什么，Agent 负责证明。第一个案例是证明 Signal 加密协议实现的关键安全性质。
Why为什么重要
形式化验证是安全保证的最高标准，过去要专家团队做几年。证明由 Lean 机械检查，Agent 写错了过不了，“AI 写的东西谁来查”有了一种不靠人逐行看的答案。
How怎么做的
多个模型把 Signal 的安全目标翻译成 Lean 规约，每条由专家审核。证明由 Gemini Carbon 驱动的 Agent 来写，分成不受信的证明组和受信的把关组。验证的是编译后的机器码，不只是协议设计。四周生成 600 多万行 Lean，人只复核 Agent 标出的约 1%。把两个已修复的旧漏洞放回隔离副本，系统两次都给出了“这版不安全”的机器证明。局限：规约仍靠专家写，只有一个案例，没有算力成本数字。页面上的行数有“三百万”和“六百万”两种说法。
Who谁
Google DeepMind，Pushmeet Kohli、Swarat Chaudhuri；Signal 的 CTO 参与评价。
When何时
11-10 发布，验证产物已开源，附技术论文。框架本身是否开放，页面没有说。Hacker News 上 652 分。
Action行动建议
挑一段最要紧、规格最清楚的代码，比如利息计算或剂量换算，先写成可检查的规约；让 Agent 写证明或性质测试，人把精力放在审规约上。

原文：Introducing AlphaProof Code: a breakthrough in verifying complex software at depth（Google DeepMind · Hacker News），11-10

产品 1招熟医疗自然语言取数

Charité｜实测医院的自然语言取数平台

有 SQL 记录的答案能查，没记录的 8 个全错

What是什么
Charité 把商用的自然语言取数平台 AIRE 接到三家医院的数据平台上，用 25 个脑肿瘤队列（1,594 人）的取数问题，和人工写的参考 SQL 逐条对比。
Why为什么重要
“让医生用大白话查数据”是医院 AI 最常见的需求之一。这篇给出一条可以直接照做的验收规则：只信能查到执行记录的答案。
How怎么做的
首轮 25 个问题：11 个完全正确，1 个对齐定义后一致，3 个错了但能从日志里的 SQL 查出错在哪；6 个看着合理却是错的，而且查不到对应的查询记录；4 个没答出来。首轮和重问合计，有 SQL 记录的 23 个回答里 22 个正确或可追溯，没有记录的 8 个全错。重问时，没有记录的错答没有再出现。部署前后用了两年，大部分花在审批、治理和 IT 部署上。局限：单一病种，只有 25 个问题。
Who谁
Charité 神经放射科和柏林健康研究所，Dmitriy Desser、Jawed Nawabi 等；平台来自以色列公司 Briya。
When何时
11-10，预印本。
Action行动建议
自然语言取数工具验收时，要求每个答案都附上实际执行的 SQL；界面上没有查询记录的数字一律标为未验证，不进报告。

原文：Natural-language cohort queries on a hospital data platform: accuracy and provenance in a real-world evaluation（medRxiv），11-10

产品 2招熟金融Visa 购物 Agent 测试

Visa｜测得购物 Agent 四成多跑不通

失败的运行里，过半还是下了单

What是什么
Visa 发布 Agentic Commerce Benchmark：15 个购物任务，比如买电视、笔记本电脑，顾客故意不把需求说全，Agent 要问出来；没有合适的商品就该不买。
Why为什么重要
这是卡组织第一次给代客下单的 Agent 出考卷。它量的不只是买没买对，还有“该不该买”，正是 Agent 支付最要紧的那道关。
How怎么做的
测了 12 家实验室的 22 个模型，平均通过 57.2%，最好 82.2%，最差 28.9%。失败的运行里 54% 仍然下了单：买了不合需求的东西，或者需求没问全就买了。同一场景跑三次全过的只有 34.2%。问出隐藏需求最多的模型通过率 70.2%，最少的 44.4%。最贵的五个模型通过 67.1%，最便宜的五个 50.2%。局限：Visa 没有公布模型名单，排名来自 Fortune 的报道，测试暂不含结账和支付环节。
Who谁
Visa；已把测试分享给主要模型厂商。
When何时
11-05 发布，Finextra 11-09 跟进。Visa 的 Payments Frontier 网站上可以自己试。Finextra 文章页拒绝抓取，以上依据 The Next Web。
Action行动建议
评测代客交易的 Agent，除了成功率，单独统计“不该做却做了”的比例；同一用例至少跑三次，按全过算分。

原文：Visa tested 22 AI models as shoppers, and they failed 42.8% of the time（The Next Web），11-05；Visa benchmark finds AI models fail 43% of shopping test runs（Finextra），11-09

Singh 等｜按等算力重比 GRPO 和密集奖励把采样成本算进去，密集奖励的排名反过来了懂劲
What是什么
论文比较 GRPO 和四种密集过程奖励（Dense Process Reward），比如从每一步采样续写来打分的蒙特卡洛奖励。比法改成“等算力”：每种方法给同样的生成 token 数和训练 GPU 小时。
Why为什么重要
后训练论文多按“每次更新”比效果，不算成本。这里续写采样就占了全部生成 token 的 91%，算上成本，结论会翻。
How怎么做的
6 个模型、1,668 次运行，预先登记实验。在 Qwen2.5-1.5B 上，蒙特卡洛奖励按每次更新领先 GRPO，等 token 时却低 14.3 个百分点，等训练时间时低 7.8 个百分点；四种密集奖励在同样训练时间下都没赢过 GRPO。单批梯度检验会把每种奖励高估一到两个点，正好和它要检测的增益一样大。挑预测成功率接近一半的题来训，等算力下有效：Qwen3-0.6B 提高 1.7 点。局限：都是 0.6B 到 1.5B 级的小模型；学习率翻倍的普通 GRPO 也能追到半个点以内。
Who谁
Vikash Singh、Vipin Chaudhary 等 19 位作者。
When何时
11-11，arXiv 预印本，读的是摘要。
Action行动建议
评估后训练技巧时，按等 token、等 GPU 小时出对照表；先试“挑难度适中的题”和调学习率，再考虑密集奖励。

SELD｜查出上下文压缩悄悄丢掉的证据答案没变，不等于证据还在懂劲
What是什么
SELD 是一个无需训练、无需标注的检测方法，找出上下文压缩（Context Compression）后答案没变、但支撑答案的证据被删掉的情况，作者叫它“静默证据丢失”。
Why为什么重要
长文档、长病历进模型前常要压缩。只核对答案会漏掉这类错误，压缩后的上下文再交给别的模型或 Agent 复用，风险会往下传。
How怎么做的
原理是证据丢了以后，模型对那些没说出口的候选答案的偏好会变，哪怕最终答案不变。比较压缩前后的这种偏好，就能发现丢失。作者用三个问答数据集做了长度匹配的删证据、删无关内容对照集 SEL-Pairs。在答案不变的配对里，SELD 找出删证据那一边的比例是 83%，最强基线 70%。
Who谁
Wentao Lei、Li Liu。
When何时
11-11，arXiv 预印本，读的是摘要。
Action行动建议
RAG 或摘要压缩上线前，评测集里加一组“删关键证据、答案不变”的样本，看你的检查能不能发现。

原文：SELD: Detecting Silent Evidence Loss in Context Compression beyond the Answer（arXiv cs.CL），11-11

What是什么
