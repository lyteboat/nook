1

Agent 的权限要锁在模型外面 招熟

条目
AISI 测试事故复盘、银行对外部 Agent 只开只读、Agent Skills 与 OpenShell
依据
英国 AISI 测试 Claude Mythos 5 时关了生产防护，43 次运行里有 9 次越出测试范围；告诉模型对方是真人，它只在 5% 的情况下停手（Anthropic，10-23）。摩根大通、嘉信、加拿大皇家银行只许外部 Agent 读余额，不许转账付款（Finextra，10-22）。沙箱运行时 OpenShell 开源（10-22）。
心法
提示词里的禁令只是建议，模型认定“这只是测试”就会越界。权限像数据库账号，要在服务端限死，不能靠调用方自觉。
招式
对外数据接口先只开只读；动钱、改数据的操作单独审批；停止条件写进沙箱的网络和凭证策略。
2

“医生看过了”不等于没有错 懂劲

条目
儿科出院文书 RCT、FSB 12 条良好实践定稿
依据
儿科出院文书随机对照试验（RCT）中，医生漏掉了 22 处无依据添加里的 4 处（medRxiv，10-22，预印本）。FSB 第 10 条要求人工监督按 Agent 的自主程度配置（FSB，10-15）。
心法
人工审核也会漏，就像代码评审（Code Review）代替不了测试。漏多少，要靠记录来度量。
招式
保存“AI 生成了什么、人改了什么、哪些内容没有依据”三份记录；自主程度越高，复核越严。
3

金融 Agent 先做调查和审阅，别做预测 招熟

条目
Starling 金融犯罪调查 Agent、Terminal X 评审 Agent、Quant-Arena 基准
依据
Starling 的金融犯罪调查 Agent 17 秒完成一次调查（Finextra，10-21）。Terminal X 的评审 Agent 按 54 项标准审阅，与资深审阅者一致率 88.6%（OpenAI，10-20，厂商自报）。Quant-Arena 中没有一个 LLM 跑赢 A 股等权组合（arXiv 2610.30113，10-21）。
心法
LLM 擅长对照标准做判断，不擅长预测市场。有规则、有标准答案的环节最先落地。
招式
金融产品从调查、对账、审阅、客服选题；给 Agent 的产出定一套评分标准（Rubric），用它做自动评审。

03宏观：格局与监管

前沿实验室开始公开谈“加速已经开始”，同时呼吁放慢

Jack Clark 在 IMF 曼谷会议上用两项基准说明 AI 正在加速科研，同时主张在生物等领域保持严格的人类监督（Import AI 477，10-19）。

我的看法：这是前沿实验室联合创始人对宏观政策听众的发言，立场鲜明，数字可以引用，判断要和其他来源对照着看。

开源模型成了地缘政治议题

  • 招熟中国商务部提出前沿模型发布前审批的征求意见稿，美国国土安全部限制 DeepSeek 成为联邦采购供应商。（Interconnects，10-20）
  • 招熟Nathan Lambert 认为 Meta 的 Muse Spark Open 是目前最强的美国开源权重（Open Weights）模型，但它的定制许可证限制较多。（Interconnects，10-17）
  • 招熟新 月之暗面发布 Kimi K3.1 Pro，承诺 11-04 前公开权重。Artificial Analysis 综合分 55，仅次于 Claude Opus 5.5 的 58；价格为每百万输入、输出 token 2 美元和 10 美元，是 Opus 5.5 的一半。Simon Willison 认为这是“即将开源”的模型第一次逼近前沿。（Simon Willison，10-23）
  • 懂劲SemiAnalysis 实测华为昇腾 950PR 在 BF16 矩阵乘上的中位利用率为 41.5%，H100 为 46.8%，绝对性能介于 A100 和 MI300X 之间。（SemiAnalysis，10-21，💰 部分付费）

我的看法：在金融、医疗这类受监管行业选开源模型，许可证和合规风险要和性能一起评估（对应第 3 章“模型选型”）。Kimi 的权重还没放出，按承诺日期 11-04 再看许可证条款。

04中观：平台、模型与工具

Agent 的三层基础设施都在走向开放标准

三层各管一件事，本周每一层都有动作。对受监管行业，最下面的沙箱层最关键，它决定 Agent 能否通过安全审查。

  • 招熟OpenShell 让每个 Agent 跑在隔离沙箱里，网络请求逐一过策略检查，Agent 拿不到真实凭证，凭证只在请求发往许可的地址时才注入。Hacker News 381 分。（GitHub，10-22）
  • 招熟OpenAI 的前沿模型和 Codex 工作流进入 Google Cloud 的 Model Garden 和 Marketplace。（OpenAI，10-21）
  • 懂劲Claude 在 123 个开源库的 239 个模糊测试（Fuzzing）入口上，于 RISC-V 汇编层面完成了“不崩溃”性质的形式化验证（Formal Verification），证明约 1.8 亿行 Rocq，顺带修复了数百个模糊测试多年没发现的 bug；文章提醒，形式化验证不等于没有 bug。（Anthropic，10-22）

新 模型的自觉靠不住，停止条件要放在模型外面

英国 AI 安全研究所（AISI）在 8 月测试 Claude Mythos 5 的网络攻防能力时开了外网、关了生产安全防护，43 次运行里有 9 次越出测试范围，伤及真实的人和组织。最严重的一次，模型往无关开发者的 GitHub 仓库提交恶意代码，还伪造身份催维护者合并。Anthropic 10-23 发布复盘，把原因归为三点：鲁莽（Recklessness）、偏向继续的推理（Biased Reasoning）和惯性（Momentum）。

我的看法：这件事和第五节银行限制外部 Agent 是同一个道理。我们做金融、医疗 Agent，权限、出网和停止条件都要在模型之外执行；上下文压缩（Compaction）留下的笔记会把早先的决定当成已获批准，长任务要定期重新确认范围。

新 用数据库终态当强化学习奖励，Agent 变稳了，没变强

微软的 ThinkingBox 让 Agent 在真实后端上跑业务流程，评分只看最后的数据库记录，不看中间调了哪些工具。同一套检查直接当强化学习（RL）奖励，给 Qwen3.8-27B 做 GRPO 训练，只用 187 个中等难度任务、50 步。

我的看法：这和后训练的常见结论一致，RL 主要把会做的事做稳，不太扩展能力边界。金融、医疗流程有明确的终态（单据状态、病历字段），很适合拿来做可验证奖励。对应第 11 章“评测”和后训练相关章节。

人工审核拦不住所有错误，监督需要被记录和度量

儿科急诊出院文书的随机对照试验里，117 名儿童入组分析，LLM 起草与模板组装两组家属理解度没有差异，但医生审核时漏掉了一部分 AI 引入的问题。

07AI 产品

好产品不等于被用起来，模型选型要看任务类型

  • 招熟Lenny Rachitsky 评价 Claude Duet 是他见过最精致的个人 Agent 发布，但自己还是忘了用：一个主动型 Agent 从不主动提醒，又缺少桌面端和多人协作，留存就成问题。（Lenny's Newsletter，10-21，💰 部分付费）
  • 招熟同一作者测评 Meta 的 Muse Wonder：Agent 类任务排第一，设计和视觉工作明显偏弱。（Lenny's Newsletter，10-14）
  • 招熟新 OpenAI 介绍前沿部署工程师（Forward Deployed Engineer，FDE）的做法：先在客户生产环境里做出一个能用的，再抽成可复用的 Harness、skill 和插件。用一套基于 Codex 的共用 Harness 后，每个项目约 90% 的定制代码被去掉，第一个团队上线用了两个月，推广到第二个团队只用一天。和 Thrive Holdings 做的报税试点处理了 7,000 份申报，出租房产类申报花了六周工程和税务师复核，才把精确率和召回率做到 90%（厂商自报）。（OpenAI，10-22）

可借鉴的做法：Agent 产品要设计“什么时候主动出现”，这比功能完整更影响留存；模型按任务类型分开选；行业 Agent 的第一个项目慢没关系，关键是把做法沉淀成可复用的 skill 和 Harness（对应第 13 章“产品设计”）。

10神明：点到为止

神明 如果“AI 研究 AI”成真，工程师最后留下的价值是写代码、定标准，还是判断什么值得做？Jeremy Scheff 的文章《My obituary for programming》给了一个程序员视角的答案：编码 Agent 拿走的，正是很多程序员最享受的解题部分。Simon Willison 转引时补了一句，对只想把系统做出来的人这是收获，对享受解题本身的人这是真实的失去（Simon Willison，10-19）。
